# S-21 — Bounded JSON structure, prototype-key filtering, and Unicode-safe validation

**Status:** DONE for the shared JSON parser and covered input schemas (2026-11-25).

**Changes:** `readJsonBody()` now defaults to a 16 KiB byte cap and a 32-container nesting cap, rejects invalid UTF-8 and excess nesting before `JSON.parse`, and recursively removes `__proto__`, `constructor`, and `prototype` keys. The streamed byte counter remains enforced before parsing. The parser rejects invalid cap configuration rather than silently weakening the guard.

`normalizeSecurityInput()` applies NFKC, folds Arabic-Indic/Eastern Arabic-Indic digits to ASCII, and removes C0/C1 controls, bidi overrides/isolates, zero-width and related invisible formatting characters. It is applied before validation to auth emails/display names/verification codes and commerce text/email fields. Password bytes are intentionally not normalized so password verification remains compatible and deterministic.

Private page and API response cache directives now use `private, no-store, no-cache, must-revalidate` and `Vary: Cookie`.

**Evidence:** `tests/hardening.test.ts` adds nested JSON rejection, prototype-key filtering, Arabic/full-width input normalization and schema coverage. `npm test`: 111 pass, 0 fail, 6 skipped (PostgreSQL integration requires `TEST_DATABASE_URL`). `npm run typecheck`, `npm run lint`, `npm run build`, and `node scripts/scan-headers.mjs http://localhost:3000` pass. Live local API response verified with no-store directives and Cookie in `Vary`.

**Scope note:** This closes these specific shared-input/cache controls only. It does not imply completion of the broader 10-pass audit or other open controls in S-01…S-20 and VULN-001…118.
